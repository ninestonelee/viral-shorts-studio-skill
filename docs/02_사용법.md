# 02. 사용법 — 한 단계씩, 화면과 함께

> 이 문서는 "각 단계에서 무슨 일이 일어나고, 화면에 뭐가 나오는지"를 설명합니다.
> 실제 수업에서는 대부분 **Claude에게 말로 시키면** Claude가 아래 명령을 알아서 실행해요. 그래도 어떤 일이 벌어지는지 알아야 결과를 믿을 수 있으니, 한 번은 읽어 두세요.

## 큰 그림 먼저

```
팩 고르기 → 시작 → 소싱 질문(✘면 멈춤) → 리서치 → 대본 N편 → 검사(✘ 0까지)
→ 소재·장면표 → 내보내기 → (영상 제작은 다른 도구) → 발행 문구 → 승인 → 게이트 → (업로드)
→ 48시간 뒤 성과 입력 → 승자 → 규칙 후보
```

이 중에서 **내가 손대는 곳은 세 번**뿐이에요.
1. 소싱 질문에 ✔/✘로 답하기
2. 대본을 읽고 "좋아요" 하기 (승인)
3. 48시간 뒤 조회수 숫자 넣기

나머지는 Claude와 프로그램이 합니다.

## 두 가지 방식: 말로 시키기 vs 직접 명령

### 말로 시키기 (평소에는 이걸로)
Claude Code에서 이렇게 말하면 됩니다.
```
/viral-shorts-studio 쿠팡 제휴로 "무선 미니 청소기" 쇼츠 3편 기획해줘. 링크는 https://...
```
Claude가 팩을 추천하고, 소싱 질문을 던지고, 리서치를 하고, 대본을 쓰고, 검사를 통과시키고, 결과 파일 위치를 알려 줍니다. 중간에 질문이 오면 답만 해 주세요.

### 직접 명령 (원리를 알고 싶을 때)
아래 모든 명령은 터미널에서 칩니다. 길어 보이지만 앞부분은 늘 같아요.
```bash
python3 ~/.claude/skills/viral-shorts-studio/scripts/vss.py -b 연습1 <할 일>
```
`-b 연습1`은 "연습1이라는 배치 폴더에서 작업해라"는 뜻이에요. **배치**는 "상품 하나로 만드는 대본 묶음"이라고 생각하시면 됩니다.

매번 긴 주소를 치기 귀찮으니 아래처럼 줄임말을 하나 만들어 두면 편해요(터미널을 닫으면 사라지니 그때마다 한 번).
```bash
V=~/.claude/skills/viral-shorts-studio/scripts/vss.py
```
그러면 이제 `python3 $V -b 연습1 check` 처럼 쓸 수 있어요.
> **파이썬이 없는 컴퓨터라면** 같은 프로그램의 Node 판 `vss.js`가 있어요. 아래 모든 명령에서 `python3 $V`를 `node $V`로 바꾸고, `V`를 이렇게 잡으면 됩니다. 나오는 화면은 똑같아요.
> ```bash
> V=~/.claude/skills/viral-shorts-studio/scripts/vss.js
> ```

## 단계 0. 장르 팩 보기

```bash
python3 $V packs
```
```
b2b        B2B · 리드 · 컨설팅 — ...
...
shop-aff   쇼핑 · 제휴(쿠팡 파트너스) — 남의 상품. 대가성 문구 필수. 소싱 2기준(효과 가시·후기 다수).
shop-own   쇼핑 · 자사 상품 — 내가 파는 상품. 1차 리뷰가 리서치 재료. 판매자 제작 표기.
```
팩 하나에 그 장르의 **소싱 질문·리서치 질문·훅 유형·금지어·표기 문구·길이 기준**이 다 들어 있어요. 팩을 바꾸면 검사 기준이 통째로 바뀝니다. 예를 들어 `health` 팩은 "치료·예방·개선"이 금지어라서 대본에 들어가면 ✘가 납니다.

## 단계 1. 배치 시작

```bash
python3 $V -b 연습1 init "미니 청소기 연습" --pack shop-aff --count 3 \
  --subject "무선 미니 청소기" --url https://example.com/p/1 --rel affiliate --notes "차량용, 노즐 1.5cm, 충전 20분"
```
```
배치 생성: /Users/홍길동/연습1 (팩 shop-aff, 3편)
```
`연습1` 폴더가 생기고 그 안에 `project.json`(모든 상태를 담는 파일)과 `rules.json`(규칙 원장), `assets/`(소재 넣는 곳)이 만들어져요.

| 옵션 | 뜻 |
|---|---|
| `--pack` | 장르 팩 이름 |
| `--count` | 몇 편 만들지 |
| `--subject` | 상품·서비스 이름 |
| `--url` | 상품 링크 (설명글과 고정 댓글에 들어감) |
| `--rel` | 나와 상품의 관계. `affiliate`(제휴)면 "쿠팡 파트너스 활동의 일환으로…" 문구가 자동으로 붙어요. `own`은 내 상품, `client`는 광고주, `none`은 판매 없음 |
| `--notes` | 메모. 리서치·대본 요청문에 그대로 들어가요 |

## 단계 2. 소싱 질문 — 이 상품, 만들어도 될까?

팩마다 2~3개 질문이 있어요. `shop-aff`는 이 셋입니다.
- `visible` 효과가 눈에 확 보이는가?
- `reviews` 후기가 많은가?
- `rights` 쓸 소재가 있는가?

답은 `y`(✔ 예) / `n`(✘ 아니오) / `alt`(△ 대체 방법 있음). "보여줄 것"은 **화면에 실제로 보일 장면**을 한 줄로.
```bash
python3 $V -b 연습1 sourcing "visible=y,reviews=y,rights=y" --show "시트 틈에 노즐이 들어가 부스러기를 빨아들이는 장면"
```
```
✔ 효과가 눈에 확 보이는가? (버튼 누르니 커튼이 스르륵)
✔ 후기가 많은가? (없으면 볼 데이터가 없다)
✔ 쓸 소재가 있는가? (상품 상세 이미지는 판매자 권리 → 캡처 사용 범위 확인, 남의 영상 금지)

소싱 통과 → 시트 틈에 노즐이 들어가 부스러기를 빨아들이는 장면
```
하나라도 `n`이면 이렇게 멈춰요.
```
✘ 효과가 눈에 확 보이는가? ...

중단: ✘ 항목이 있어요. 소재를 바꾸거나 대체(alt) 방안을 정하세요.
```
이게 이 스킬의 첫 번째 철학이에요. **안 될 상품에 시간을 쓰지 않는다.** 화면에 보이지 않는 효과(예: "피부가 좋아진다")는 쇼츠로 팔기 어렵습니다.

## 단계 3. 리서치 — 상상 금지, 출처 필수

```bash
python3 $V -b 연습1 prompt research
```
화면에 긴 "요청문"이 나옵니다. 이건 **Claude에게 줄 지시문**이에요. 말로 시킬 때는 Claude가 이 요청문을 스스로 읽고 웹을 검색해 리뷰·커뮤니티 글을 모아 옵니다. 핵심 규칙은 요청문 첫 줄에 있어요.

> 상상으로 쓰지 말고, 실제로 확인한 공개 출처(리뷰·커뮤니티·기사·지침)만 쓰고 모르면 lv=3(미확인)으로 표시하라.

결과는 JSON 파일로 저장하고 반영합니다. 연습에서는 미리 만들어 둔 예제를 쓰세요.
```bash
python3 $V -b 연습1 ingest research ~/Documents/viral-shorts-studio-skill/examples/sample_batch/research_raw.json
```
```
리서치 반영: 발화 5건(출처 없음 0), 트렌드 2건
```
"발화"는 **실제 사람이 한 말**이에요. 예제 파일을 열어 보면 이렇게 생겼습니다.
```json
{"quote": "차 안 과자 부스러기는 손으로 털어도 시트 틈에 남는다", "src": "쿠팡 리뷰 #88213", "lv": 0, "hook": "시트 틈 부스러기, 손으로 털지 마세요"}
```
`lv`는 출처 등급이에요. 0 = 리뷰·문의 원문, 1 = 커뮤니티·후기, 2 = 기사·2차 인용, 3 = 미확인. 출처가 비어 있으면 이런 경고가 나와요.
```
△ 출처 없는 발화가 있어요 — R-001: 발화 100%에 출처
```

## 단계 4. 대본 N편 쓰기

```bash
python3 $V -b 연습1 prompt plan
```
역시 요청문이 나오고, Claude가 그걸 수행해 대본 JSON 배열을 만듭니다. 요청문이 요구하는 것:
- 편마다 **훅 유형을 다르게** (불편형·상황극형·감탄형…)
- 첫 문장은 리서치 발화를 변형해서
- 대사 3~5문장, 그중 **"가장 센 문장" 하나만** strong=true
- 숫자는 리서치에 있는 것만, 금지 표현 0개

연습에서는 예제 대본을 반영합니다.
```bash
python3 $V -b 연습1 ingest plans ~/Documents/viral-shorts-studio-skill/examples/sample_batch/plans_raw.json
```
```
플랜 3편 반영
```

### 검사 — 여기가 핵심
```bash
python3 $V -b 연습1 check
```
```
[1편] ✘ 불편형 · 추정 19초 · 훅 린트 38점(The Question)
  제목: 차 시트 틈 과자 부스러기, 손으로 털지 마세요 (3가지 이유)
  ✘ 장면: 1번 컷 소재 없음
  △ 추정 19초 (목표 25~35)
  △ 훅 린트 38점(WEAK) — 약한 곳: 손실·위험 → 지금 방식을 유지하면 잃는 것 한 줄 [보정 전 휴리스틱]
  △ 썸네일이 제목과 겹침: 부스러기,시트,틈
  △ 장면: 1번 컷 6.8초 — 핵심 등장이 3초를 넘길 수 있음
  △ 장면: 소재 미지정 4컷 (검정 화면)

...

오류 있음 — 발행 불가
```
읽는 법:
- **✘ = 오류.** 고치지 않으면 발행 못 해요. 여기서는 "1번 컷에 소재가 없다"가 오류예요. 아직 사진을 안 넣었으니 당연합니다(다음 단계에서 해결).
- **△ = 경고.** 읽고 판단해서 고치는 것. "추정 19초인데 목표는 25~35초"는 대사를 조금 늘리라는 뜻이고, "썸네일이 제목과 겹침"은 썸네일 글자와 제목이 같은 말을 반복한다는 뜻이에요.
- **훅 린트 38점(WEAK)** — 첫 문장의 힘을 5가지(구체성·호명·손실위험·호기심·간결성)로 본 점수예요. 어디가 약한지와 처방이 함께 나옵니다. "[보정 전 휴리스틱]"이라고 적힌 이유는, 이 점수가 실제 조회수와 맞는지 아직 10편 넘게 쌓아 보지 않았기 때문이에요. 참고만 하세요.

검사가 보는 항목 전체는 [viral-shorts-studio/references/gates.md](../viral-shorts-studio/references/gates.md)에 표로 있어요.

### 첫 문장만 따로 점검하고 싶을 때
```bash
python3 $V lint "차 시트 틈에 낀 과자 부스러기, 손으로 털어도 안 나오죠?"
```
```
"parts": {"구체성": 34, "호명": 26, "손실·위험": 22, "호기심": 59, "간결성": 100},
"v": 38, "band": "WEAK", "formula": "The Question",
"weak": "손실·위험", "fix": "지금 방식을 유지하면 잃는 것 한 줄"
```
"손실·위험"이 22점으로 가장 약하니, "그대로 두면 곰팡이 냄새가 납니다"처럼 **안 하면 잃는 것**을 한 줄 넣으라는 처방이에요. 수업에서 첫 문장을 고쳐 가며 점수가 오르는 걸 직접 보는 실습을 합니다.

## 단계 5. 소재 등록과 장면표

사진·영상을 등록할 때는 **역할**과 **권리**를 꼭 적어요.
```bash
python3 $V -b 연습1 asset 연습1/assets/nozzle.jpg --role "사용 장면" --rights "직접 촬영"
python3 $V -b 연습1 asset 연습1/assets/review.png --role 화면 --rights "직접 촬영"
```
```
소재 a8c10: nozzle.jpg · 사용 장면 · 직접 촬영
소재 a11d8: review.png · 화면 · 직접 촬영
```
앞의 `a8c10` 같은 글자가 소재 번호예요. 이걸 대사 컷에 붙입니다.
```bash
python3 $V -b 연습1 scene --plan 1 "1=a8c10,2=a8c10,3=a11d8,4=a8c10"
```
```
[1편] ✔ 불편형 · 추정 19초 · 훅 린트 38점(The Question)
  △ 장면: 1번 컷 6.8초 — 핵심 등장이 3초를 넘길 수 있음
```
✘가 ✔로 바뀌었어요. 권리를 `미확인`으로 등록한 소재를 장면표에 넣으면 다시 ✘가 납니다. **남의 사진·영상을 쓰지 않는다**는 규칙(R-005)이 코드에 들어 있는 거예요.

## 단계 6. 내보내기

```bash
python3 $V -b 연습1 export --plan 1
```
```
  → 연습1/exports/script_1.json
  → 연습1/exports/factory_1.md
  → 연습1/exports/script_045_1.txt
  → 연습1/exports/publish_1.md
  → 연습1/exports/research.md
  → 연습1/exports/content_plan.md
```
수업에서 쓰는 건 두 개예요.
- **factory_1.md** — 영상 제작용 대본. Hook / Body / CTA / Shots 순서라 캡컷·브루에 그대로 붙여도 되고, `shopping-shorts-factory` 스킬에 넘기면 영상이 나옵니다.
- **publish_1.md** — 유튜브·틱톡·인스타 발행 문구.

`factory_1.md`는 이렇게 생겼어요.
```markdown
# 차 시트 틈 과자 부스러기, 손으로 털지 마세요 (3가지 이유)

> 장르 팩: 쇼핑 · 제휴(쿠팡 파트너스) · 훅: problem · 목표 25~35초 · 720p
> 표기: 쿠팡 파트너스 활동의 일환으로 수수료를 제공받습니다

## Hook
차 시트 틈에 낀 과자 부스러기, 손으로 털어도 안 나오죠?

## Body
이 미니 청소기 노즐은 폭이 1.5cm라 틈 안으로 그대로 들어갑니다.
리뷰 88213번 분도 같은 고민이었다고 해요.

## CTA
링크는 고정 댓글에 있어요.

## Shots
1. 0~3초: 시트 틈 클로즈업, 손가락으로 털다 실패 (핵심 등장)
2. 노즐이 틈에 들어가 빨아들이는 장면 (★ 센 문장, 자막 크게)
3. 리뷰 캡처 화면
4. 엔딩, 깨끗한 시트 틈 → 처음 장면으로 루프
```

## 단계 9. 48시간 뒤 성과 넣기

올린 지 48시간이 지나면 유튜브 스튜디오에서 조회수와 "계속 시청 비율"을 봅니다. 모든 편이 **같은 나이(48시간)**일 때만 비교해야 공정해요.
```bash
python3 $V -b 연습1 perf --plan 1 --v48 900 --stay 58 --click 7
python3 $V -b 연습1 perf --plan 2 --v48 2400 --stay 66 --click 21 --conv 1
python3 $V -b 연습1 perf --plan 3 --v48 400 --stay 41 --click 2
python3 $V -b 연습1 winner
```
```
n=3 승자: 카시트 밑 청소 포기했던 분, 20분이면 차 한 대 끝 (상황극형) 점수 4604
      패자: 미니 청소기 흡입력 약하다는 후기, 부스러기 1분 테스트 결과 (랭킹형) 점수 400

[규칙 후보] 이 소재는 상황극형 훅, 1번 컷 7.5초가 48h 기준 우세. 다음 배치에서 재현되면 규칙으로 올린다 (R-007).
점수식은 가설: v48×(1+stay/100) + click×20 + conv×200
```
| 옵션 | 뜻 |
|---|---|
| `--v48` | 48시간 조회수 |
| `--stay` | 계속 시청 비율 % |
| `--click` | 링크 클릭 수 |
| `--conv` | 주문·가입 등 전환 수 |

"규칙 후보"는 **아직 규칙이 아니에요.** 한 번 이긴 걸로 규칙을 만들면 우연에 끌려갑니다. 다음 배치에서도 같은 훅이 이기면 그때 규칙 원장에 넣습니다.
```bash
python3 $V -b 연습1 rule --stage ss-plan "이 상품군은 상황극형 훅이 2배치 연속 우세" --source "연습1·연습2 승자"
```
