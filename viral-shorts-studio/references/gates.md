# 검사 항목 · 발행 게이트 · 규칙 원장

모두 `scripts/vss.py` 코드가 판정한다. 폴라는 결과를 읽고 고치는 쪽이다.

## check (플랜 검사) — ✘ 오류 / △ 경고

| 구분 | 항목 | 기준 |
|---|---|---|
| ✘ | 금지어 | 팩 `banned[]` + 리서치 `banned_add` 가 제목·썸네일·설명·대사·태그·플랫폼 문구 어디에도 없음 |
| ✘ | 센 문장 | `strong=true` 정확히 1개 |
| ✘ | 표기 문구 | 팩 `disclosure` 앞 6자가 설명에 포함 |
| △ | 길이 | 추정 초(공백 제외 글자수 ÷ 4.5)가 `duration[min-5, max+5]` 안 |
| △ | 핵심 등장 | 1번 컷 shot에 핵심/제품/결과/현장/등장 중 하나 |
| △ | 태그 | 5개 이상 (10개 권장) |
| △ | [확인 필요] | 남아 있으면 경고, approve·gates에서는 차단 |
| △ | 숫자 출처 | 대사에 숫자가 있으면 출처(src) 있는 발화가 1건 이상 |
| △ | 훅 린트 | 첫 대사 5속성(구체성·호명·손실위험·호기심·간결성) 가중 점수 <45면 약한 속성과 처방. 인사·"오늘은" 시작, 과장어 별도 경고. **보정 전 휴리스틱** |
| △ | 제목 | 100자 초과 오류급 경고, 60자 근처 잘림, 과장어, 숫자·날짜 없음 |
| △ | 썸네일 | 제목과 어절 겹침, 4어절/14자 초과 |

## scene (장면표 검사)

| 구분 | 항목 |
|---|---|
| ✘ | 1번 컷 소재 없음 |
| ✘ | 권리 `미확인` 소재 사용 (R-005) |
| △ | 1번 컷 역할이 정면/사용/현장/화면/비교 아님 |
| △ | 1번 컷 길이 > coreAppearSec+1 |
| △ | 소재 미지정 컷 (검정 화면) |
| △ | 총 길이 범위 밖 |

장면 길이 기본값은 대사 글자수 비례 배분(총 길이 = max(duration.min, 추정 초)). `project.json`의 `plans[].scenes[].sec`를 직접 고칠 수 있다.

## gates (발행 게이트 12개 — 전부 ✔이어야 upload)

1. 굿 승인 기록 (`approve`)
2. 플랜 검사 오류 0
3. 장면표 검사 오류 0
4. [확인 필요] 0
5. 소재 권리 미확인 0 (배치 전체)
6. 다른 편과 대사 3-gram 자카드 유사도 < 50% (부모 폴더의 모든 배치 대상 — 반복 대량 생산 방지)
7. 이 편 미업로드 또는 실패/누락 확정 (unknown은 재시도 금지)
8. 오늘 업로드 < cap (기본 2, unknown 포함)
9. 직전 업로드와 gap 시간 이상 (기본 6h)
10. 영상 파일 존재
11. ffprobe: 세로(h>w) · 180초 이하
12. `VSS_YT_TOKEN` 환경변수

업로드 상태값: `unknown`(시작 직후·결과 불명) → `done`(응답 수신) → `verified`(videos.list 확인) / `verified-missing` / `failed`.

## 규칙 원장 기본 7개 (templates/rules.json, 050 하네스 호환)

| id | stage | 규칙 |
|---|---|---|
| R-001 | ss-plan | 리서치→플랜 먼저. 발화는 실제 발화만, 항목마다 근거 링크 |
| R-002 | ss-plan | 편마다 훅 유형 다르게 → 성과에서 승자 |
| R-003 | ss-clone | 레퍼런스는 구조만. 연속 6어절 동일 0, 남의 영상 파일 미사용 |
| R-004 | ss-render | 핵심 첫 3초, 25~35초, 720p |
| R-005 | ss-render | 소재마다 권리 기록, 미확인 소재 금지 |
| R-006 | ss-publish | 표기 문구 모든 플랫폼·영상 하단, 업로드는 "굿" 이후 |
| R-007 | ss-perf | 같은 48h 나이에서만 비교, 승자는 후보 → ㅇㅇ → 2배치 재현 시 확정 |

새 규칙: `vss.py rule --stage ss-perf "규칙문" --check "검사법" --source "출처"`. stage는 ss-plan / ss-clone / ss-render / ss-publish / ss-perf.
